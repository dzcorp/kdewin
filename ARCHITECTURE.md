## Pipeline
`lumen gen` reads `tokens/tokens.toml` and writes:
- `build/gen/cpp/lumentokens.h` — constexpr tokens for C++ (CMake `LUMEN_GEN_DIR`).
- `build/out/` — install tree:
  - `share/…` → `~/.local/share/…` (user) or `/usr/share/…` (system)
  - `config/…` → snippets applied by `lumen apply`
  - `system/…` → root-only (plymouth, limine, vconsole, pacman hook)
  - `apps/…` → firefox, kitty, alacritty

Static package sources (`plasma/`, `kwin/effects-js/`, `boot/`) are copied by `assemble`:
- text files get `@@path.to.token@@` replaced (mode-specific keys use `@@color.dark.x@@`).
- every dir holding a `.qml` that references `LumenTokens` receives generated `LumenTokens.qml`.
- `plasma/look-and-feel/common/` merges into each variant (`dark/`, `light/`).

`lumen build` = gen + cmake (`build/cmake`) + ninja. `lumen install` = user data; `--system` = sudo cmake install + system files + pacman hook. `lumen apply [dark|light|auto]`. `lumen doctor` checks effect load and falls back to stock blur.

## Colors at runtime
Accent always from KDE (`Highlight`). Fluent fills come from the token tables, chosen by palette luminance (`window` lightness < 0.5 = dark). Accent shades: OKLCH algorithm in `[accent]`, identical in Rust (`color.rs`), C++ (`common/lumencolor.cpp`), QML (`LumenTokens.qml`).

## Ownership
- `tools/lumen/` Rust generator and installer
- `common/` C++ shared code: colors, shadows, tokens include
- `kcm/` System Settings module (C++ KQuickManagedConfigModule + `ui/` FormCard pages); `bench/` style benchmark
- `style/` QStyle · `decoration/` KDecoration3 · `kwin/effects/materials/` C++ effect · `kwin/effects-js/` JS
- `plasma/desktoptheme` generated by Rust (`desktoptheme.rs`)
- `plasma/look-and-feel/`, `plasma/plasmoids/`, `plasma/shell-overlay/` static sources plus placeholders
- `plasma/tray/` C++ containment: `src/` forked from plasma-workspace 6.8.3 (GPL-2.0+), `dbusmenuqt/` (LGPL), `qml/` ours
- `upstream/forks.toml` upstream release of every fork; `lumen upstream sync` merges newer releases three-way
- `packaging/aur/` PKGBUILDs; `lumen install --destdir` stages the package (data root `/usr/share/lumen/root`, Dolphin in
  `/usr/lib/lumen/bin` put first by `/etc/xdg/plasma-workspace/env/lumen.sh`), `lumen pre-remove` undoes runtime state
- `plasma/tasks/` forked from plasma-desktop 6.8.3 taskmanager (GPL-2.0+): icons only, `iconSize` config, exact (unsnapped) icons; `lumen apply` swaps a stock icontasks for it in place

## Layout migration
`lumen apply --layout` reads the bottom panel from `plasma-org.kde.plasma.desktop-appletsrc` before the reset and writes
`~/.config/lumen-layoutrc` (`[Layout]`, `[LayoutWidget-N]`); the L&F layout script rebuilds extras, launchers, Start favorites
(same KAStats client id as the old Kickoff) and tray lists from it. Old tray children's settings are then copied onto
the Lumen tray's children and plasmashell restarts.

## Runtime settings
`lumenrc` groups: Appearance, Materials, Decoration, Style, Animations, LockScreen. `kcfg.rs` writes the KConfigXT schema
with token defaults. Readers: `common/lumenconfig` (style + decoration; style watches with KConfigWatcher, decoration
reloads on `DecorationSettings::reconfigured`). On save the module mirrors values to kwinrc (`Effect-lumen_*`, plugin
toggles, decoration buttons), kscreenlockerrc and the panel (plasmashell `evaluateScript`), then asks KWin to reconfigure.
Root actions (boot, login, refresh-shell, rebuild-kwin) run `lumen` through pkexec.
